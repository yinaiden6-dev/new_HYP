# Route A N2 fresh-D1 matched three-arm Pair64 training-pair scope corrective addendum V1

## Purpose and precedence

This narrow append-only addendum corrects an over-broad Pair64 requirement in
Sections 4 and 5 of
`ROUTEA_N2_FRESH_D1_MATCHED_THREE_ARM_REMATERIALIZATION_CONTRACT_V1_20260904.md`,
SHA256
`6d1eb7515ed739cb74a1d955c8fa077fc1033df8a7e1b06757b02c1eabdf54f3`.

The parent text can be read as requiring full-C128 target-free A/B/C maps and
features for both current64 and Pair64 before any label join. That is correct
for current64 deployment/evaluation records but is unnecessarily strong for
Pair64 training-only records and is not what the earlier frozen N2 design
specified.

This addendum controls only that Pair64 distinction. It does not modify any
current64 artifact, score, feature, validation, threshold, model or result.
Every other parent-contract prohibition remains in force.

## Corrected Pair64 boundary

For Pair64, the mandatory target-free preseal contains exactly:

1. the fixed 64-query query-ID/order roster;
2. unique joins to the canonical 987-query ledger;
3. each query's fold-compatible fresh-D1 OOF checkpoint binding;
4. the complete 5,413-row score vector and corrected 5,412-identity ranking;
5. the natural fresh-D1 C128 axis and base winner;
6. adapted query-token and source-image receipts;
7. zero target identity, target position, target rank, correctness, outcome,
   supergroup, action or historical target/competitor consumption.

The target-free Pair64 preseal does not compute 64 x 128 local RoMa maps or
A/B/C feature bundles.

Only after that base-axis artifact is independently sealed may a separate
training-only process join the Pair64 target identity and apply the already
frozen three-branch rule:

- target is the fresh-D1 winner: pair the winner with fresh D1's strongest
  wrong and assign negative HOLD;
- target is naturally in C128 but is not the winner: pair the base winner with
  that target as the positive challenger;
- target is absent from C128: pair the winner with fresh D1's strongest
  non-winner and assign negative HOLD.

The join selects exactly two distinct candidates per query: the base winner
and one training counterpart. It does not insert a target, widen or reorder
C128, or select from a local score.

## Training-only local feature computation

After the fixed pair is joined, compute A ALL, B QUERY and C PAIRED evidence
for both selected endpoints using the same frozen query/reference images,
canonical geometry, RoMa checkpoint, ColNomic tokens, score formula, roll
controls and six native feature definitions as the current64 mechanism.

The local feature function remains target-independent: it receives a query and
a specific candidate reference, not a target label or outcome. The target is
used only by the supervised sampler to select the training counterpart from an
already sealed natural C128. This is ordinary training supervision and cannot
be used as target-free evaluation evidence.

Exactly 128 RoMa pair evaluations are required: two endpoints for each of 64
Pair64 queries. All 128 are recomputed through the frozen RoMa path. Historical
postjoin Pair64 maps, arm scores, features or actions are not reused. The narrow
exact-map cache-reuse addendum remains applicable to current64; it does not
authorize Pair64 postjoin map reuse.

## Pair64 controls that remain out of scope

Pair64 supplies training pairs only. It does not materialize:

- a full 127-challenger negative matrix per query;
- Pair64 fullnegative episodes;
- Pair64 shift-64 C_BIND evaluation;
- candidate-reorder or retrieval metrics as a scientific endpoint;
- a Pair64 challenger selected by a trained action head.

C_BIND and deployed own-strongest-challenger evaluation remain target-free
current64 responsibilities. C_BIND is inference-only and never enters Pair64
training.

## Validation and combined lineage

Independent validation must maintain two visibly separate namespaces:

1. `PAIR64_TARGET_FREE_BASE_PRESEAL`: 64 full-gallery/C128 base records with
   zero protected-field access;
2. `PAIR64_POSTSEAL_TRAINING_PAIR_FEATURES`: 64 fixed training pairs, 128 fresh
   RoMa evaluations and their A/B/C features after supervised join.

The validator must prove that the postseal stage changes no presealed score,
rank, axis, winner, fold binding or query source. It must reconstruct the
three-branch pair choice independently, verify both endpoints belong to the
presealed natural axis except for the explicitly retained target-absent HOLD
case where no target endpoint exists, and verify target insertion remains zero.

A later combined handoff may bind:

- the validated current64 full-C128 target-free aggregate;
- the validated Pair64 target-free base preseal;
- the independently validated Pair64 postseal training-only feature artifact.

It must not claim that all 128 queries possess target-free local feature
bundles. Its correct claim is that current64 inference features were sealed
target-free and Pair64 supervised training features were produced only after a
separately sealed natural base axis.

## Claim boundary

This correction does not authorize code execution by itself. It authorizes a
separate frozen Pair64 execution contract and later execution authority.

Neither a Pair64 preseal nor postseal training artifact may claim target
discovery, candidate recall, retrieval improvement, candidate binding, spatial
ownership, deployment readiness or scientific GO/NO-GO. Only the later
seven-parameter cross-fit contract may consume the validated training artifact,
and current64 remains its only internal deployment/evaluation population.
