already-frozen natural ColNomic C128 set, P must independently emit


1. one connected query-side region with at least four distinct patches;
2. at least two distinct corresponding reference-side atoms;

4. a signed proposal score computed only from atoms inside that legal region.

`H0` is always present with exact score `+0.0`.  If P cannot form a legal
region, or if every legal H1 score is non-positive, H0/no-match wins.

A GO under this contract means only:

## 6. Candidate-specific atom construction

The mathematical core receives no rank-like field.  For every valid query
patch `i`:

1. sample the RoMa A-to-B warp and overlap at the canonical query-cell centre;
2. map the continuous reference coordinate to the nearest valid canonical
   reference patch `j(i)`;
3. sample the B-to-A warp, reverse overlap, and both precision matrices;
4. compute the continuous cycle error back to the query-cell centre;
5. compute ColNomic cosine between the query token and the assigned specific-
   reference token, and subtract the query-to-reference-token mean cosine;
6. write one immutable atom with query cell, reference cell, continuous forward
   and reverse coordinates, overlaps, precision summary, cycle error, content
   hashes, and assignment hash.

No overlap, cosine, cycle, or precision threshold is applied.  An atom is
structurally invalid only for non-finite arithmetic, an invalid canonical cell,
or a continuous warp outside the reference image.

Define bounded values:

```text
c       = assigned ColNomic cosine
c0      = mean cosine from that query token to all tokens of this reference
dc      = c - c0
oq, or  = query and reverse RoMa overlap in [0,1]
rho     = sqrt(oq * or)
chi     = exp(-4 * L2 continuous cycle error)
pi      = tanh(log1p(max(0, minimum eigenvalue of the two sampled symmetric precision matrices)))
e       = dc * rho * chi
```

The fixed selector feature is exactly:

```text
[c, dc, oq, or, rho, chi, pi, rho*dc, e]
```

Feature dimension is 9.  The shared selector is one FP64 `Linear(9,1)`, ten
trainable scalars including bias.  It has no identity, candidate, position, or
slot parameter.

## 7. Sparse selection, connected H1, and exact H0

For one candidate, prepend one fixed H0 logit of exact zero to all valid atom
logits and apply sparsemax over the complete valid atom axis.  Invalid atoms
have exact zero weight and never enter the axis.  Only atoms with strictly
positive sparsemax weight are selectable.

Two selectable atoms share an edge iff:

1. their query grid cells are exact 4-neighbours; and
2. their assigned reference grid cells have Chebyshev distance at most 2.

This fixed local compatibility scale is not scanned.  Connected components are
formed on that graph.  A legal H1 requires:

```text
at least 4 distinct query patches;
one exact query-side 4-connected component;
at least 2 distinct reference atoms;
complete atom-level assignment/geometry provenance;
one candidate/reference source binding.
```

For component `C`, its signed H1 score is the sparse-weighted mean of `e_i`
over `i in C`.  No atom outside `C` may enter its score.  Components are ordered
by descending H1 score, then canonical atom-ordinal tuple, and the first fixed
eight are emitted.  Missing slots are exact H0 padding.  `K=8` is frozen and
will never be scanned.

The candidate proposal score is the fixed nine-slot log-mean-exp of H0=0 and
the eight H1 scores, with H0 padding retained.  The candidate H1 decision uses
`max_k H1_k > 0`; exact ties select H0.  If no legal H1 exists, the candidate
score is positive-zero bit-exactly.

This is the only REAL candidate-score path.  Direct atom pooling, all-patch
MaxSim, global scores, raw selector logits, visibility mass, proposal count,
and pre-merge AS1 candidate score are forbidden from the REAL reducer.

Every H1 seal includes the exact query indices/mask, reference indices/atoms,
source atom ordinals, atom weights/evidence, continuous warp coordinates,
reverse coordinates, cycle/overlap/precision records, and a canonical logical
hash.  A separate replay reconstructs every field from the atom bank.

## 8. Frozen matched controls

All arms use the same C128 population, query/reference tokens, atom bank,
feature dimension, ten-parameter linear capacity, update count, and labels.

### 8.1 REAL candidate-conditioned P

The selector sees the nine candidate-specific atom features.  Only legal
connected H1 regions enter the candidate score.

### 8.2 Same-capacity all-patch/no-HYP

A separate `Linear(9,1)` produces softmax atom weights and a weighted mean of
`e` over the complete valid atom set.  It has no connected region and is
explicitly a reranker control, never HYP.

### 8.3 Candidate-independent query-only region

A separate `Linear(9,1)` sees only a nine-dimensional deterministic function
of query-token norms, query-token four-neighbour self-contrast, and normalized
query coordinates.  It selects query cells with sparsemax and forms query 4CCs
without reading any candidate.  The same region population is replayed for
all 128 candidates; candidate evidence may be read only inside those query
regions.  This is a comparator, not a candidate-conditioned hypothesis.

### 8.4 C_BIND

A hash-fixed no-fixed-point permutation moves the **complete reference-derived
atom bank** among the 128 destination candidate keys before selector inference.
Query, destination axis, complete donor feature/coordinate/provenance tensors,
and donor content bindings are preserved.  It never shuffles sealed scores or
H1 outputs.  TRAIN and EVAL use disjoint namespaces.

### 8.5 P_COORD

Two hash-fixed, no-fixed-point, non-affine permutations independently rebind
the complete atom content rows to query and reference coordinate rows before
component construction.  Feature tensors, token tensors, element counts,
norms, valid masks, coordinate sets/multisets, candidate keys, and atom
assignment provenance are preserved; only token/atom-to-coordinate association
changes.  The selector and full connected-region reducer rerun after the
destruction.  TRAIN and EVAL namespaces and realizations are distinct.

### 8.6 Candidate reorder

Candidate reorder changes only enumeration order.  After key alignment, all
atom banks, hypotheses, scores, H0 decisions, and controls must be bit-exact.
It is an invariance test, not a destruction control.

## 9. Optimization-only fit

Labels are joined only after every one of the 32 TRAIN C128 atom banks and its
independent validation are sealed.  Exact-pair identity is used only by the
loss; it is never added to the forward input or candidate set.

Three ten-parameter heads (REAL, all-patch, query-only) are trained separately
in FP64 with:

```text

learning rate = 0.03
weight decay = 0
updates = 512 (16 deterministic epochs over 32 queries)
gradient clipping = none
checkpoint/model selection = final update only
threshold/K/top-M/feature/loss scan count = 0
```

REAL uses the frozen loss:

```text
L_real = CE(REAL C128 scores, target)
       + softplus(- strongest target H1 score)
       + 0.25 * softplus(strongest wrong REAL score)
       + softplus(C_BIND target score - REAL target score)
       + softplus(P_COORD target score - REAL target score)
```

The all-patch and query-only controls each use:

```text
L_control = CE(control C128 scores, target)
          + softplus(- target control score)
          + 0.25 * softplus(strongest wrong control score)
```

Every update must have finite loss and finite gradients.  The parameter count,
initial state, complete deterministic query sequence, optimizer state, and
final checkpoint are sealed.  No natural result chooses an intermediate
checkpoint.
