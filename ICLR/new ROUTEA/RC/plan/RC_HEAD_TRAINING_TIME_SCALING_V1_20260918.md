# 32／128／593 训练耗时补充

用户要求拟合当前三种规模的训练耗时，并更新完整结果文档和指定 ZIP。

历史 FULL32/FULL96/FULL128 的实际计时保留（5139291，原训练与独立重放各一次），但它们均有额外 PAIR64。当前 H593 COST1/CE 不采用同一 PAIR64 混合配方，不能把历史 32/128 与当前 593 直接拼成训练规模定律。

补充同配方计时：同一 CPU 节点、8 线程、FP64、原 AdamW、2000 步、零初始化。直接调用冻结 COST1/CE 的原 train 函数。三组分别取原 H593 outcome-blind execution order 的前 32、前 128、全部 593 张，嵌套且不看本轮预测；target 缺自然 C128 时沿用原 loss 排除规则，同时报告选入与实际拟合数量。

每种配方先在 32 pool 热身一次（不纳入拟合），然后每个规模测 3 次，共 18 次正式计时。按预定循环移动规模执行顺序。只记录参数 SHA，重复参数必须相同；593 的参数需与原冻结头在 2e-10 内一致，原头文件 SHA 不变。计时参数不注册、不评价准确率、不替换生产头。

用 perf_counter 包围完整原 train 调用，包含优化器创建和 2000 次更新；排队、解释器启动、缓存读取、特征构建、冻结编码器和 RoMa 前向、结果评价均不算入纯头训练时间。额外准备耗时另存。GPU 仅用于进入已授权的短时分区，训练在 CPU 上，不称 GPU 训练耗时。

每种配方以三种规模的中位数拟合 T(N)=a+bN；N 为实际进入 loss 的 query 数。显示全部重复点、范围与拟合线，标明 32/128/593 pool 与有效数，提供残差和 R²。只有三个规模，不能据此声称普遍复杂度规律；不向更大规模外推。历史同配方 32/96/128 的 6 个记录单列图表，593 的历史完整作业时间若读取则与纯 train 计时分开。
