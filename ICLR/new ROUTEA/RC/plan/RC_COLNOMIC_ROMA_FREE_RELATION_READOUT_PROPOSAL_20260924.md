# 从 RoMa 来源归因到无 RoMa 的检索关系读出

日期：2026-09-24。状态：研究方案；未实现新训练器，未提交新作业，未得到新模型结果。

用户本轮目标：解释 RoMa 提供什么、现有检索器为什么没有直接使用这些证据，并提出推理时完全不调用 RoMa 的改造。这个分支与此前“保留真实 M、学习内部使用”的实验分别记录；后者的结果不能当作无 RoMa 的成功。

## 1. 可检验的命题

候选局部内容相似，并不保证这些相似关系在双图之间能够共同成立。工作假设是：现有晚交互评分对局部最大相似度的汇总，未充分使用软对应分布之间的相互关系；在冻结 ColNomic tokens 上增加联合关系读出，可能直接学到有用的候选区分，不必先生成或拟合 RoMa 的绝对 M。

这不是已经证明的统一根因。RoMa 的视觉表示、预训练任务、训练数据规模和联合读出仍有混杂。新实验只能先验证一个建设性命题：同一套冻结 tokens 能否通过另一种读出产生可泛化的纠错。

RoMa v2 的共视/overlap监督来自深度或光流循环一致性，提供了与检索身份监督不同的先验。其成功不能仅归因于算子形式。[RoMa v2，第3节](https://arxiv.org/html/2511.15706v1)

## 3. 评分层的确定性质，与未证实的经验解释

固定已经编码的 tokens，记 `C_ij = cosine(q_i, r_j)`，自由内容分数为 `L = mean_i max_j C_ij`。

对于任意 reference 列置换 Π，`L(CΠ)=L(C)`。如果只打乱相似度与 reference 坐标的绑定而不重编码，局部相似度的集合不变，但其排列关系可以改变，MaxSim 本身无法响应这种改变。这是评分函数的性质，不是“图像重排后编码器输出不变”的命题。上下文化 tokens 自身可能已经包含空间和全图内容，不能称所有检索器都没有结构信息。

待检验解释：原评分保留“各patch分别像什么”，对“这些对应是否相互支持”读取不足。现有 RoMa 干预只为这一解释提供动机，尚未证明它就是 ColNomic 失败的原因。

## 4. 具体改造位置与接口

```text
query/reference -> 冻结 ColNomic -> 已缓存的最终 tokens 与坐标
                                      |
                          全部有效 token 相似度 C
                           /                       \
                  原自由 MaxSim L            可学习联合关系读出 R
                           \                       /
                            检索评分 / HOLD-SWITCH
```

改造在 LLM 和检索投影之后、MaxSim 聚合之前。候选条件计算仅发生在轻量关系模块，不需要按候选重跑 LLM。原图库 tokens 可继续复用。它是检索器交互读出的改造；当前还不是更新 ColNomic 主干表示的实验。

一个可实现的首版算子：

1. 构造完整 C、双向软对应 A/B 和归一化 patch 坐标，不提前取硬对应或候选相关 top-K。
2. 为每个潜在对应 `(i,j)` 建立关系状态，读取内容相似度及双向匹配信息。
3. 在双图坐标确定的邻域中，对不同 `(i,j)` 进行共享、可学习的消息聚合，再汇总成候选关系证据 R。实现可用分解的局部相关张量卷积，避免显式建立所有对应之间的平方级图。局部算子只是待验证的结构先验，不设置仿射通过门、唯一对应或空间 ownership 门。
4. 保留自由内容分支，用零输出初始化的关系残差接入候选评分。对照共享同一评分/接受接口，初始化必须重放为无关系分支的行为。

这样训练的是对身份任务有用的关系证据。训练和推理均不读取 RoMa 的 M、粗细特征或伪对应；不以 M 的绝对数值为目标。RoMa 仅作为独立已知系统的比较对象。

这与旧蒸馏的关键差别有两项：学习目标从复制 M 改为区分正确 reference；可学习联合处理发生在对应结构被压成逐patch摘要之前。旧六臂本身已有身份训练，因此不能把“改用身份标签”单独当成相对六臂的新改动。

## 5. 最小隔离，而非直接扩成新一轮全量搜索

固定原候选来源、完整自然 C128、原 identity/source 分组、相同训练/校准预算。先在一个预先固定的组划分完成可拟合性及留出分析；原fold0已多次查看，所得证据只能称开发组留出，不能称全新独立确认。

|对照|需要回答的问题|
|---|---|
|原 MaxSim + 同预算评分/接受头|仅重训末端是否已能产生收益|
|旧压缩关系读出，接相同末端协议|新方法是否只是又训练一次旧质量网络；历史负结果只作参照，不能替代同协议对照|
|联合相似度读出，不提供坐标邻域|完整匹配竞争是否足够，不必依赖空间排列|
|联合相似度读出 + 正确坐标邻域|跨patch位置关系是否提供额外贡献|
|同一已训练结构读出，坐标绑定扰动与一致变换对照|收益是否使用正确的结构绑定；输入扰动不能单独排除分布外退化|
|同一面板的真实 RoMa + 已验证外部头|无 RoMa 替代达到多少已知效果；与主模型结构不同，作为系统参照单列|

可学习臂应尽量匹配参数量、训练样本呈现次数及优化预算；参数量、更新时间和优化步数分别报告，不把同样步数误写成同样计算量。结构读出与无坐标读出应共享输入数值、状态宽度和末端，改变的是邻域信息；若无法严格等容量，明确记录。

第一关是训练能否利用关系输入、梯度是否有效、输入干预是否沿设计通路改变预测。下一关才是跨组的候选区分及净增；同时记录损失原正确的数量。不要求32/32成功，也不预设必须超过 RoMa。

“有效”与“达到原效果”分别判定：有跨组稳定净增可支持该改造有效；接近或替代原 RoMa 系统还需预先定义容许差异并报告配对区间，不能由差异不显著直接宣布等效。原 C128 外目标不补入，计入全样本结果。

## 6. 计算复用与归因留存

旧计划 `RC_H593_PAIR_QUALITY_V1_20260923.md` 记录完整软矩阵可从不可变 tokens、坐标和固定温度重建。旧520维/压缩上下文缓存不足以还原所有联合关系，必须读原 token 来源。正式实现前核验缓存哈希、patch坐标和有效token掩码，特别是特殊token不能伪造空间邻域。

无需重新运行 RoMa 或图像/LLM 编码器，但重建矩阵及联合关系训练不是零成本。先实测单query完整C128的运行时间和峰值内存，再确定CPU或GPU任务；不先承诺CPU可快速跑完整593。

保留：源tokens/坐标/候选顺序绑定、网络与优化器断点、完整逐候选 L/R/logit、分组预测、训练梯度和关系层关键统计。完整高维中间量可用固定输入和模型断点重建；固定少量诊断query保存逐层关系状态，不能仅保留最终检索结果。

## 7. 新颖性边界与结果解释

跨对应邻域一致性及仅凭匹配/不匹配图像对训练已有 NC-Net；冻结局部描述子、最优传输和匹配聚合已有 ELViS。不能把“可学习关系模块”“retrieval-only”“跳过RoMa”单独宣布为首创。[NC-Net](https://arxiv.org/abs/1810.10510)，[ELViS](https://arxiv.org/html/2603.28603v1)。MaxSim 的独立局部最大值汇总也来自已有晚交互框架。[ColBERT](https://arxiv.org/abs/2004.12832)

可争取的实质结果是：通过受控比较定位晚交互的具体读出不足，并构造一个无需额外匹配器、保留内容自由度的补偿机制。它是否区别于已有方法、是否足以构成论文贡献，取决于实际机制、与这些邻近方法的比较和跨数据结果，不能从方案本身下结论。

成功将建设性证明：在已测试的冻结表示和数据范围内，至少一部分 RoMa 带来的作用可由检索器自身读出实现。失败只能限制该模块、训练及数据，不能证明 tokens 没有所需信息或 RoMa 必不可少。先完成这一分界，再决定是否需要训练编码器。
