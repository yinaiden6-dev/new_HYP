用户要求先完成可以供后续复用的前置数据。本次为工程执行更新：不修改候选、模型权重、原训练目标、原干预定义或已封存结果。

旧 RoMa 的最终 u/v、M、C4 和旧 ColNomic tokens 继续直接复用；融合分支所需的 5324 份 token 对齐特征已经完整缓存，保留其训练任务。

## 第一项前置数据

将原始 LR800 输入的两层完整 DINO 特征按实际输入 tensor SHA 去重持久化，保留原生 dtype、shape 和值。复用现有已验证图像目录，不重新检索、不新增标注。粗特征每图约 10.24MB；全量约 55GB，实际按去重清单统计。旧 token 池化特征不能反推出这两层完整网格。

不先无差别保存全部细特征：按当前 shape 和 BF16 估计每图另约 510MB，全量约 2.7TB。细特征读取未必比 VGG 重算便宜。第一阶段只在自然首例测其计算/存读成本，不把未实测收益当成加速。后续需要细特征的流程继续按配对在内存复用；不能称全部上游状态都已缓存。

同时缓存 token 池化的整数框。保持原 FP64 切片、mean、stack 顺序，只省去每个分支每个阶段重复计算相同边界。原生完整前向输出和池化结果必须逐位一致。

## 资格与自动顺序

1. 首个自然 query 全部 C128：旧完整前向与共享粗特征读取前向逐位比较；池化与原源码逐位比较，包含所有原生/细化分辨率的真实图像网格。
2. 记录真实磁盘读回和完整 forward 耗时；粗缓存若不能减少该首例的完整前向时间，停止扩展。计时是工程先导，不是全量速度保证。
3. 通过后只编码目录中尚未缓存的原始图片，按输入 SHA 和原图 SHA 记录来源。每 15 分钟分片在约 600 秒正常保存并退出，afterany 控制器仅对 COMPLETED/0:0 续跑。
4. 全部唯一图像缓存完成并复核文件 SHA 后，才恢复坐标、视觉来源、内部通路三组。新执行器读取共享缓存；视觉变换后输入未命中时仍需编码。原有完整 query 和部分文件继续复用，不重新覆盖。

三个旧机制数组及其回调仅暂缓待运行项；运行片自然完成。原数组后续仅在替代执行器、共享缓存和资格全部就绪后收口。新任务仍沿用原独立科学验证器。优先恢复内部通路，其次视觉来源、坐标；不增加实验臂。

内部通路沿用用户指定的 dev_accelerated，以每批 3 项适应当前提交额度；视觉来源和坐标各自按 accelerated 每批至多 46 项恢复。控制器使用 CPU 分区，读取通过验证的结果清单，跳过已完成 query。全量缓存未就绪时不启动新消费者。

缓存和工程记录在 `cache/rc_h593_shared_native_v1/`；原模型科学输出位置保持不变。缓存未覆盖的跨图交互、坐标干预细化、变换图像编码仍需计算，速度收益由实测报告。
